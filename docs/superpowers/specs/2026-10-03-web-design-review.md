# Web デザイン改修・セルフチェック

2026-10-03

## デザイン方針

「その質問が、秘密をほどく。」を軸に、紙・墨・朱色のパレット、ゴシックと明朝の対比、秘密のお題と YES / NO のカードでゲームの世界観を表現する。装飾は CSS / SVG で制作し、外部 CDN、Web フォント、新しい実行時依存は追加しない。トップだけでなく、参加、待機、出題、質問、正解、招待、確認、接続切断を共通のデザインにする。

参考にした評価の観点は、[Webby の審査基準](https://www.webbyawards.com/judging-criteria/)の視覚表現・機能・構造と導線・インタラクション・総合体験、および [Awwwards のモバイル評価ガイド](https://www.awwwards.com/mobile-excellence-guidelines.pdf)。受賞や公式審査での評価を確認したものではない。

## 改善の反復

1. **構図と世界観**：幅 560px の単列画面を再設計。デスクトップは二列のヒーロー、モバイルは開始操作を先に置く。独自カード、ロゴ、遊び方、待機時の説明、入室画面を制作。PC / スマホの実表示を確認。
2. **プレイ中の視認性**：スマホで回答の文字製バーが折り返される問題を発見。既知の回答形式だけを専用カードと `meter` に変換し、質問・判定・両方の割合を表示。未知の形式は本文へフォールバック。出題者・質問数・経過時間の視覚階層を整理。
3. **操作と境界条件**：小画面でヘッダー・フォームが操作欄を押し出さないようスクロールを制御。文字のコントラスト、44px の補助操作、フォーカス表示、動きを減らす設定への対応を調整。ギブアップ確認も共通のダイアログに変更。別ゲームへの遷移で古い確認を閉じる。他のボタンのスペースキー操作でマイクが起動する問題を修正。

## 検証結果

| 項目 | 確認内容 |
| --- | --- |
| トップ画面 | 1440×1000、390×844 でスクリーンショット確認。横はみ出しなし |
| ゲーム画面 | 390×844、320×568、667×375。最小幅と横向きで横はみ出しなし、操作欄がビューポート内 |
| 複数人 | localhost と 127.0.0.1 の別ストレージを使って2人で参加。接続者一覧が同期 |
| ゲーム進行 | 名前入力 → ルーム作成 → 招待 QR → 出題 → 文字質問 → 判定中 → 割合表示 → 正解 → 次のお題 |
| お題の秘匿 | 出題者にだけ秘密を表示。回答者側では非表示 |
| ダイアログ | 招待、遊び方、ギブアップ確認。キャンセルと公開、Escape とフォーカス復帰を確認 |
| 再読込 | トークンで復帰し、履歴と役割を再表示 |
| 切断 | 検証サーバー終了後「再接続中…」を表示し、操作を無効化 |
| コード検証 | Python 188 passed / 4 integration deselected、JavaScript 17 passed、`git diff --check` 成功 |
| 追加テスト | 回答割合の保持、改行・HTML風文字列、未知形式のフォールバック、他の操作やダイアログ中の音声ショートカット抑制 |

ゲーム進行のブラウザ確認には専用ポート 8081 と決定的なテスト用判定器を使用。既存の 8080 サーバーは停止・再設定していない。検証サーバーは確認後に停止。

マイクの実音声認識、カメラの実 QR 読み取り、実機 iOS / Android、実際の外部判定 API は今回のブラウザ検証対象外。実機性能・正式なアクセシビリティ監査・各賞の審査を代替するものではない。

## 実装上の注意

- ゲームの中核・WebSocket のプロトコル・Discord 側は変更していない。
- 回答カードは `answer.js` が既存のサービス本文を解析する。サービスの書式を変える場合はテストも更新する。解析できない本文はそのまま表示される。
- 見た目のために `innerHTML` は使わず、参加者名・お題・質問は引き続き `textContent` で表示する。
- カードのホバー、入場アニメーション、録音状態のパルスは `prefers-reduced-motion` で停止する。
