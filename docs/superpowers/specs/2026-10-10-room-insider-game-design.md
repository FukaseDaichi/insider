# ルームのインサイダーゲーム 設計

Web 版のお題当てルームの中で、インサイダーゲームを遊べるようにする。参加者をタップで選んで役職を配り、AI（Jev）が GM として「はい／いいえ」で答え、当たったら画面で投票してインサイダーを探す。

## 目的

いまのルームは、出題者がお題を出し、AI が答え、出題者も質問者に紛れて遊べる（インサイダーゲームに近い遊び方ができる）。ただし配役・お題の秘匿・インサイダー探しは参加者どうしの口頭に任せていた。これをルームの中で完結させる。配役ツール（`/village`）を別に開かなくても、ルームだけでインサイダーゲームの 1 回が始まって終わる。

## 範囲

対象:

- ルームに「インサイダーゲーム開始」を足し、参加者の選択・お題の決め方・制限時間を選んで始める
- 役職（インサイダー 1 人・村人）を参加者それぞれの画面にだけ配る
- 質問は参加者だけに許す
- 当たったら投票し、開票で勝ち負けを出す
- 制限時間（分単位）

対象外:

- いまの「お題を出す」のゲームへの制限時間
- 話し合いの時間を計るタイマー
- Discord 版へのインサイダーゲーム
- 人の GM（「はい／いいえ」は常に AI が答える）

## 遊び方の流れと決まり

### 始める

- ルームで誰も遊んでいないとき（お題当てのゲームが進行中でなく、インサイダーゲームがお題待ち・質問・投票のどれでもないとき）、「お題を出す」の隣に「インサイダーゲーム開始」を出す。ルームの誰でも押せる。
- 押すと設定のシートが開く。
  - **参加者**: ルームの参加者の名前が並び、タップで選ぶ・外す。最初は接続中の全員が選ばれている。始める人が自分を外してもよい。3 人以上を選ぶ（インサイダー 1 人と村人 2 人。2 人では投票が成り立たない）。上限はルームの上限（20 人）。
  - **お題の決め方**:
    - **ランダム（既定）**: 配役ツールのランダム村と同じく、辞書の「初心者」の範囲から選ぶ（`VillageService.pick_topic(BEGINNER_RANK)`）。辞書が使えないときは、この選択肢を断って知らせる。
    - **自分で決めて配る**: 始める人がお題（1〜50 文字）を打つ。お題を知るので、始める人は参加者から外れ、選べなくなる。
    - **インサイダーが決める**: 役職を配ったあと、インサイダーの画面にだけお題（1〜50 文字）の入力欄を出す。決まった時点でお題当てのゲームが始まる。それまでほかの参加者には「インサイダーがお題を考えています…」と出す。
  - **制限時間**: 既定はなし。オンにすると 1〜30 分の分単位で決める（オンにしたときの初期値は 5 分）。時間はお題当てのゲームが始まった時点から数える（インサイダーが決める場合は、決めた時点から）。
- 「配って始める」で、選ばれた参加者の中からインサイダーを 1 人、くじで選ぶ。ランダムと自分で決める場合は、その場でお題当てのゲームを始める。

### 配る

- 参加者には、自分の画面にだけ役職のカードを出す。画像は配役ツールの役職画像（`Illustrations.url_for("INSIDER" / "VILLAGERS")`）。インサイダーのカードにはお題も載せ、村人のカードには載せない。
- カードはインサイダーゲームが終わるまでいつでも開き直せ、再読み込みや再接続（`snapshot`）でも戻る。
- 参加者に選ばれなかった人は見るだけ。質問・投票・ギブアップ・開票はサーバーが断る。会話欄と結果は見える。

### 質問の時間

- いまのお題当てと同じく、AI が「はい／いいえ」で答える。参加者は全員（インサイダーも）質問できる。
- 制限時間があるときは、上のバーの経過時間の代わりに残り時間を出す。
- 結末は 3 通り。
  - **時間内に誰かが当てた**: 投票へ進む。正解の演出（テロップ・声・クラッカー）はいまと同じ。
  - **時間切れ**: 全員の負け。お題と、誰がインサイダーだったかを出す。
  - **ギブアップ**: 参加者が押せる。時間切れと同じく全員の負け。インサイダーがお題を考えている間に押すと、そこで中止する（全員の負け）。

### 投票

- 参加者全員（インサイダーも）が、自分以外の参加者 1 人に投票する。開票までは入れ直せる。話し合いはその場や通話で行う。
- 誰が投票し終えたかは全員に見せるが、誰に入れたかは開票まで見せない（サーバーも送らない）。
- 参加者全員が入れたら開票する。接続が切れた人を待たずに締めたいときは、参加者の誰かが「開票する」で締め切れる（確認つき）。1 票も入っていなければ締め切れない。
- 勝ち負け:
  - 最多票がインサイダー 1 人だけ → 村人の勝ち
  - 最多票が別の人、または同票 → インサイダーの勝ち
- 開票のカードに、インサイダー・お題・各人の得票・勝ち負けを出す。誰が誰に入れたかは出さない。

## 作り

### サーバー

- **`web/insider.py`（新規）**: インサイダーゲームの 1 回分（`InsiderRound`）の状態と決まり。ネットワーク・asyncio・`GameService` に依存しない。
  - 持つもの: 参加者の player_id の列、インサイダーの player_id、お題、段階（`choosing` お題待ち → `asking` 質問 → `voting` 投票 → `done` 終わり）、締め切りの時刻、投票（投票者 → 相手）、結末（当たり・時間切れ・ギブアップ・開票の結果）。
  - 決まり: 参加者の検査（3 人以上、ルームの参加者であること、自分で決めるなら始める人を含まないこと）、くじ（乱数は差し替えられる）、投票できるか、全員が入れたか、開票と勝ち負け。
- **`web/rooms.py`（変更）**: `Room` にいまのインサイダーゲーム（`InsiderRound | None`）を持たせる。終わった回も次のゲームを始めるまで残し、役職のカードを開き直せるようにする。`Entry` に種類（`kind`）と中身（`data`）を足し、結果のカードを文字の読み解きではなく構造で描けるようにする（既存の記録は `kind` なし）。
- **`web/hub.py`（変更）**: ルームの進行役に操作を足す。
  - `insider_start`: 入力を検査し、`InsiderRound` を作ってくじを引く。お題があれば `GameService.start` で始める（出題者は参加者でない番兵の ID と「GM」の名前。`setter_can_ask=True` で全員が質問する）。始まりの案内を会話欄に足し、開始の声を鳴らす。
  - `insider_topic`: インサイダーだけが `choosing` のときに受け付け、`GameService.start` で始める。
  - 質問（`ask`）: インサイダーゲームが `asking` なら、参加者でない人の質問を断る。AI が当たりと判定した（`Outcome.is_correct`）ら `voting` に進め、投票の案内を足す。
  - ギブアップ（`giveup`）: インサイダーゲーム中は参加者だけが押せる。`GameService.giveup` で終え、インサイダーを明かした全員の負けのカードを足す。
  - `vote` / `close_vote`: 参加者だけが受け付ける。全員が入れたか締め切られたら開票し、結果のカードを足す。
  - 時間切れ: 締め切りに `loop.call_later` で予約を 1 つ置く。時刻になったら、そのゲーム（game_id）がまだ続いているときだけ時間切れで終える。当たり・ギブアップで先に終わったら予約を取り消す。ルームが片付けられたときはゲームも消えるので、発火しても何もしない。テストでは時間切れの処理を直接呼ぶ。
  - お題の辞書と役職画像は、配役ツールの `VillageService`（`pick_topic`・`illust`）を `RoomHub` に渡して共有する。辞書は起動時に 1 回だけ読む。
- **`web/server.py`（変更）**: `insider_start`・`insider_topic`・`vote`・`close_vote` を受けて `RoomHub` に渡す。型の違う値は黙って捨てる（いまの `start` と同じ）。

### 画面とのやりとり（WebSocket）

画面からサーバー:

| type | 中身 |
| --- | --- |
| `insider_start` | `participants`（player_id の列）、`topic_mode`（`random` / `self` / `insider`）、`topic`（`self` のとき）、`minutes`（制限時間。なしは `null`） |
| `insider_topic` | `topic` |
| `vote` | `target`（player_id） |
| `close_vote` | — |

サーバーから画面:

- `room` の `players` の各人に `id`（player_id。連番で秘密ではない）を足す。名前は重なりうるので、選択と投票は ID で行う。
- `room` に `insider` を足す（インサイダーゲームがなければ `null`）。
  - 全員に: `phase`、`participants`（ID の列）、`remaining`（残り秒。制限時間がなければ `null`）、`voted`（投票し終えた ID の列）。
  - その人の接続にだけ: `you`（`role`: `insider` / `villager` / `null`（見るだけ）、`topic`（インサイダーで、お題が決まっていれば）、`image`（役職画像の URL）、`vote`（自分が入れた相手）)。
  - 終わった回は `result`（インサイダー・お題・得票・勝ち負け・結末）も全員に入れる。
- 役職とお題は、いまの「お題は出題者の接続にだけ入れる」と同じく、`_room_state` を接続ごとに作るところでだけ入れる。ほかの接続にも、見るだけの人にも、誰がインサイダーかは終わるまで送らない。
- 会話欄の記録: 始まりの案内（参加者の名前とお題の決め方。お題は書かない）、投票の始まり、時間切れ・ギブアップ・開票の結果のカード（`kind: "insider_result"`、`data` に結果）。

### 画面

- **`index.html`**: 「インサイダーゲーム開始」のボタン、設定のシート（参加者のタップ選択・お題の決め方・制限時間）、自分の役職のカード（開き直すボタンつき）、インサイダー用のお題の入力欄、投票のパネル（参加者の名前の大きなボタンと「開票する」）を足す。
- **`insider.js`（新規）**: 画面の判断だけを持つ純粋関数。設定の検査（人数・お題・制限時間）、選べる参加者（自分で決めるなら自分を外す）、残り時間の表示、投票できる相手、結果の表示の組み立て。
- **`insiderview.js`（新規）**: 上の部品の描画。`app.js` は `room` の `insider` と `insider_result` の記録を受けて渡すだけにする（`app.js` はすでに 846 行あるため）。
- 押せるものは 44px 以上。参加者の選択と投票は名前ごとの大きなボタンにする。文字は `textContent` で描く。

## エラーと境界

- 入力の誤り（人数が足りない・お題が空や長すぎ・制限時間が範囲外・ルームにいない ID）は、押した人にだけ `notice` で知らせて何もしない。
- ゲーム中に別のゲーム（お題を出す・インサイダーゲーム開始）を始めようとしたら断る。投票中も断る（締め切れば次を始められる）。
- お題待ちのままインサイダーが抜けたら、参加者のギブアップで中止できる。
- 投票中に参加者が抜けても投票は続く。残りの人で「開票する」で締め切れる。
- サーバーの再起動ではルームごと消える（いまと同じ）。

## テスト

- **pytest**
  - `insider.py`: 参加者の検査、くじ（乱数を固定）、投票の可否（自分・参加者でない人・段階違い）、入れ直し、全員が入れたかの判定、開票（インサイダーが単独最多・別の人・同票）。
  - `hub.py`: ランダム・自分で決める（始めた人が外れる・始めた人を選ぶと断る）・インサイダーが決める（インサイダー以外のお題を断る）の 3 通り、見るだけの人の質問・投票を断る、当たり → 投票 → 全員の投票で開票、「開票する」での締め切り、時間切れ（直接呼ぶ。先に終わったゲームでは何もしない）、ギブアップ、役職とお題が他人の接続・見るだけの人・再接続の `snapshot` に漏れないこと。
  - `server.py`: 新しい 4 つのメッセージを受け、型の違う値を捨てること。
- **node のテスト**: `insider.js` の判断。
- **画面の確認**: 手元のサーバーで、内蔵ブラウザから 1 人目を操作し、2 人目以降はスクリプトで WebSocket につないで遊ぶ（同じブラウザだとルームの合言葉を共有して同じ人になるため）。配る → 質問 → 当たり → 投票 → 開票、時間切れ、インサイダーがお題を決める流れをスマホ幅で確かめる。当たりは本物の Jev で判定する。
