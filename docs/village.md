# 村の外部仕様

村（インサイダーゲームと Werewords の配役）の外部仕様。ここに書かれた入力と応答の対応が、LINE と Web の両方の入口が守る契約である。設計上の位置づけは [仕様書](spec.md) の「村の中核」。

村への操作は 2 通りで届く。テキスト（LINE のトークなど）と、構造化された操作（作成・設定・参加を 1 つずつ呼ぶ形）である。テキストは、数値の境界とコマンド表で入力を解釈し、構造化された操作を呼ぶだけである。ゲームの規則は構造化された操作の側にだけあり、同じ入力には、どちらの経路でも同じ応答が返る。

## 村の種類

| 種類 | 番号 | 作成方法 | 用途 |
| --- | --- | --- | --- |
| 通常村 | 4 桁 | `お題` / `題` | インサイダーゲーム。オーナーは配布役に徹する |
| 神モード村 | 4 桁 | `神` | インサイダーゲーム。GM を 1 人立てる |
| 逆村 | 4 桁 | 通常村・神モード村を `@逆村` で切替 | インサイダーゲームの変種。お題を知らない人が 1 人 |
| ランダム村 | 4 桁 | `ランダム`（隠しコマンド） | オーナーも参加者になる。お題も自動 |
| 特殊村 | 5 桁 | Web 版の特殊村フォーム（`/village/special`） | 任意のメッセージ集合を配る汎用の村 |
| Werewords 村 | 5 桁 | 通常村を `@わーわーず` で変換 | Werewords。実体は特殊村 |

村の種類は番号の桁数で決まり、参加者は桁数を意識する必要がない。4 桁でも 5 桁でも、村番号を送れば自分に割り当てられたメッセージが返る。

番号は空いているものからランダムに採番する。通常村は 1000〜9999、特殊村は 10000〜99998。連番ではないので隣の番号を推測しにくいが、総当たりを防ぐ強度はなく、認証の代わりにはならない。

## 入力の解釈

テキストは次の順で判定する。

1. 前後の U+0020 以下の文字（半角スペース・タブ・改行）を除く。**全角スペース（U+3000）は除かない。**
2. 数値として読めれば数値。
3. 定義されたコマンドに完全一致すればコマンド。
4. それ以外はすべてお題。

この規則は、LineBot（Java 実装）の `String.trim()` と `Integer.parseInt()` と同じである。Python の標準の関数は、全角スペースを除いたり、`1_0` や範囲外の値を数値として読んだりと、受け付ける範囲が広く、同じ入力で応答が変わってしまうため、これらには任せない。

### 数値

数値として読むのは、符号（`+` `-`）を 1 つだけ付けてよい 10 進数字の列で、32 ビット整数（-2147483648〜2147483647）に収まるもの。全角数字（「３」）やアラビア・インド数字も 10 進数字として読み、先頭の 0 は読み飛ばす。次は数値ではなく、お題になる。

- BMP の外にある数字（`𝟑` など）
- `1_0`、`3.0` のような数字以外を含む列
- 数字の間にある空白（前後の空白は先に除かれる）
- 32 ビット整数の範囲外の値

| 入力値 | 動作 |
| --- | --- |
| 10000 以上 | 特殊村へ参加 |
| 1000〜9999 | 通常村へ参加 |
| 101〜999 | 村番号として扱う（該当なし） |
| 100 以下（0 と負数を含む） | 人数設定 |

設定できる参加人数は 100 人までで、101 以上は村番号として解釈される。**101〜999 を送ると、必ず「対象の村がない」応答が返る。** 村番号は 1000〜9999 で採番されるので、この範囲に該当する村は存在しない。

### コマンド

前後の空白を除いた入力が、次のいずれかと完全に一致したときだけコマンドになる。`@` は半角と全角（`＠`）のどちらでもよい。

| 入力 | 動作 |
| --- | --- |
| `お題` / `題` | 通常村を作る |
| `神` | 神モード村を作る |
| `ランダム` | ランダム村を作る（隠しコマンド） |
| `@逆村` | 逆村に切り替える |
| `@わーわーず` | Werewords 村に変換する |
| `@取得` | お題の候補を取得する |
| `@配布` | 友だち追加の案内を表示する |
| `@特殊` | 特殊村フォームの URL を表示する |

### お題

数値でもコマンドでもない入力は、すべてお題として扱う。`@あ` のような定義されていない `@` 付きの文字列もお題になる。

お題には、前後の空白を除く前の入力をそのまま使う。全角スペースで囲んだ `　3　` や `　神　` は、数値にもコマンドにもならず、そのままお題になる。

お題の設定は「自分が所有する村のうち、お題がまだ未設定の最新のもの」を対象とする。そのような村がなければ、村の作成を促す既定の応答（[対象の村がない場合](#対象の村がない場合)）になる。お題は一度しか設定できない。

## 通常村

### 手順

1. オーナーが `お題` または `題` を送る。村が作られ、4 桁の村番号が返る。応答には「お題の自動取得」ボタンが付く。
2. オーナーがお題を送る。
3. オーナーが参加人数を送る。この時点で配役が抽選される。
4. オーナーが参加者へ村番号を口頭で伝える。
5. 参加者が村番号を送る。参加順に役職が返る。
6. オーナーが村番号を送ると、配布状況とお題が返る。

手順 2 と 3 は順不同である。人数も「自分が所有する村のうち、人数がまだ未設定の最新のもの」を対象とする。

お題が未設定のまま人数を決めた村では、役職メッセージとオーナーの配布状況のお題が `『null』` と表示される（「お題は『null』です。」）。Java の文字列連結が未設定の値を `null` と書くのと同じ表示である。

神モード村（`神`）の手順も同じで、人数の案内の例が「GM１人、インサイダー１人、村4人」になる。

### 役職

| 役職 | 人数 | 知る情報 |
| --- | --- | --- |
| インサイダー | 1 人 | お題を知る |
| 村人 | 残り全員 | お題を知らない |
| ＧＭ | 神モードのみ 1 人 | お題と配布状況を知る |

役職名の「ＧＭ」は全角である。Werewords の「GM」は半角である。

### 配役の決まり方

参加人数を確定した時点で、**インサイダーになる参加順の位置**が 1 から人数の範囲で抽選される。神モードではさらに **GM になる位置**が抽選され、インサイダーと同じ位置になった場合は引き直される。

参加者は、村番号を送った順に 1 番目、2 番目…と席に着く。自分の位置が抽選された位置と一致すればその役職、しなければ村人である。

この方式には次の性質がある。

- **配役は参加者が誰であるかに依存しない。** 抽選されるのは席の位置だけで、誰がその席に着くかは参加した順で決まる。
- **人数を確定した時点で配役は決まっている。** 参加者が集まるのを待たずに抽選が完了しているため、全員が揃わなくても配布を始められる。
- **満席になるまで、抽選された役職が全員に行き渡るとは限らない。** 5 人村に 3 人しか参加しなければ、インサイダーが不在のまま始まる可能性がある。これは仕様であり、人数を守るのは利用者の責任である。

### 参加人数

- 2 人以上を指定する。1 以下を送ると、再入力を促すメッセージが返り、人数は設定されない。
- 100 人まで。101 以上は村番号として解釈される。
- 人数は一度しか設定できない。人数が未設定の村が自分になければ、数値を送っても「対象の村がない」応答になり、設定済みの村は変わらない。

### 参加

- 参加者が村番号を送ると、参加順に応じた役職が返る。
- **同じ人が再度送ると、同じ役職が再表示される。** 席は増えない。自分の役職を忘れても、何度でも確認できる。
- 参加人数に達している村へ新しい人が参加しようとすると `村がいっぱいです。` が返る。
- **オーナーがまだ参加人数を設定していない村**へ参加者が村番号を送った場合も、同じ `村がいっぱいです。` が返る。人数が未設定の村は定員 0 として扱われるためで、意図した挙動である。オーナーが人数を設定した後に再送すれば参加できる。
- オーナー自身は着席しない。オーナーが村番号を送ると、参加者としての役職ではなく配布状況が返る（ランダム村を除く）。
- 存在しない村番号を送ると、「対象の村がない」応答が返る。

### 配布状況の確認

役職メッセージには「入室状況確認」のボタンが付く。押すと、自分が何番目の参加者かと、現在の入室人数が返る。参加していない人が確認すると 0 番目と返る。

オーナーが村番号を送ると、入室人数とお題を含む配布状況が返る。人数設定の応答に付く「確認」ボタンと、配布状況に付く「再確認」ボタンは、どちらも村番号を送るのと同じである。

## 逆村

`@逆村` で、**自分が所有する村のうち、参加者がまだ 1 人もいない、ランダム村でない最新のもの**を逆村へ切り替える。人数やお題が未設定でも切り替えられる。参加者が 1 人でもいる村は切り替えられない。切替の前後で配役の規則が変わるため、混在すればゲームが成立しないからである。対象の村がなければ「対象の村がない」応答になる。

逆村では、インサイダーと村人の役職が入れ替わる。インサイダーとして抽選された位置の人が村人となり、それ以外の全員がインサイダーになる。結果として**お題を知らない人が 1 人だけ**の村になる。

神モード村を逆村へ切り替えた場合、GM は GM のままである。入れ替わるのはインサイダーと村人だけである。

ランダム村は対象外である（後述）。

## ランダム村

`ランダム` で作成する。**村の作成を促す既定の応答（後述）が案内する選択肢には含まれない隠しコマンド**である。利用者へ提示する選択肢を増やさずに、慣れた利用者だけが使える経路として残している。

通常村との違いは次の 3 点である。

1. **お題を聞かない。** 作成時に「初心者」の難易度の範囲からお題が自動で選ばれる。辞書が使えないときは、お題は未設定のまま作られる（[お題辞書](#お題辞書)）。
2. **オーナーも参加者になる。** 人数を確定した時点でオーナーが 1 番目の参加者として着席し、その場で自分の役職が返る。他の参加者が入れるのは**設定した人数から 1 を引いた数**である。
3. **GM が常に立つ。** 神モードと同じく、GM とインサイダーがそれぞれ 1 人抽選される。

そのため、オーナーが村番号を送っても配布状況ではなく**自分の役職**が返る。オーナーは他の参加者と同じ立場であり、お題を含む配布状況を見せてはならないためである。人数がまだ未設定の場合は、人数設定を促すメッセージが返る。

逆村への切り替えはできない。逆村はインサイダーを複数人にする変種であり、GM とインサイダーを 1 人ずつ配るランダム村とは配役の前提が両立しない。Werewords 村への変換もできない（人数を決めた時点でオーナーが着席するため、参加者のいない村という条件を満たさない）。

## 特殊村

インサイダーゲームに限らず、**任意のメッセージ集合を参加順に 1 通ずつ配る**汎用の村である。Web 版の特殊村フォーム（`/village/special`）で、配りたいメッセージを送って作成する。

- フォームは 1〜100 通、1 通あたり 5,000 文字までを受け付ける。空のメッセージは許す。検証は番号を採番する前に行う。空の村には誰も参加できず、長すぎるメッセージは LINE が送信を拒否するので、番号を利用者へ伝えた後に使えないと分かる村をレジストリに残さないためである。
- メッセージはランダムに並べ替えられてから配られる。送信した順序は配布順にならない。
- 参加者数の上限は、送ったメッセージの数である。上限に達した村へ参加しようとすると `村がいっぱいです。` が返る。
- 同じ人が再度参加すると、同じメッセージが再表示される。
- 空のメッセージを割り当てられた参加者には `メッセージは特にありません。` が返る。
- 参加者のメッセージにも「入室状況確認」のボタンが付き、押すと自分が何番目の参加者かと入室人数が返る。
- 役職の抽選も、お題の概念もない。何を配るかは作成する側が決める。

## Werewords 村

`@わーわーず` で、自分が所有する通常村・神モード村を Werewords 村へ変換する。

**変換の対象**は、自分が所有する村のうち、**参加者がまだ 1 人もいない最新のもの**である。その村が次の両方を満たす場合だけ変換される。

- 参加人数が 3 人以上に設定済み
- お題が設定済み

対象の村がない場合、および対象の村が上記を満たさない場合は、「対象の村がない」応答になる。**条件を満たす古い村へ遡って探すことはしない。**

**変換後の扱い**

Werewords 村は特殊村として新しく作られ、5 桁の番号が採番される。元の通常村はそのまま残るため、**参加者へ伝える番号は新しい 5 桁の方**である。メッセージは特殊村と同じく並べ替えられて配られる。

**役職**

占師 1 人、インサイダー 1 人、残りは村人である。このうち 1 つの役職が「欠け」として場から取り除かれる。

| 役職 | 受け取るメッセージ |
| --- | --- |
| 占師 | `あなたの役職は占師です。お題は「<お題>」です。` |
| インサイダー | `あなたの役職はインサイダーです。お題は「<お題>」です。` |
| 村人 | `あなたの役職は村人です`（お題は伝えない。末尾の「。」はない） |
| GM | `あなたの役職はGMです。お題は「<お題>」です。` に続けて、改行して `役職は「<欠けた役職>」が欠けています。` |

- **神モード村から変換した場合**: 配布メッセージは人数分である。そのうち 1 通は GM 向けで、どの役職が欠けているかを伝える。
- **神モードでない村から変換した場合**: 配布メッセージは人数 + 1 通になる。オーナー自身も入室し、**オーナーが受け取った役職が欠けた役職**として扱われる。変換の応答がこの旨をオーナーへ案内する。

## お題の自動取得

`@取得`、または村作成時に返るメッセージの「お題の自動取得」ボタンで、お題の候補を 1 つ取得する。村を持っていなくても引ける。

返るメッセージには次のボタンが付く。

| ボタン | 動作 |
| --- | --- |
| 確定 | 表示中の候補を、そのまま自分の村のお題として設定する |
| 初心者 | 易しい範囲から引き直す |
| 上級者 | 難しい範囲から引き直す |
| 変態 | 最も難しい範囲から引き直す |

「確定」ボタンは、表示中の候補をそのまま送信するメッセージボタンである。つまり**お題の設定は通常の自由文入力と同じ経路**を通る。候補を見てから自分で別の言葉を打ってもよい。

### 難易度の範囲

お題は辞書から引く。辞書は難易度（1〜5）の昇順に並んでおり、難易度は辞書内の範囲として表現される。

| 難易度 | 引く範囲 | 同梱の辞書での範囲 |
| --- | --- | --- |
| 初心者 | 難易度 1〜3 | 先頭 5,084 語 |
| 上級者 | 難易度 3〜4 | 955〜7,646 語目 |
| 変態 | 難易度 5 | 7,647〜8,436 語目 |
| 指定なし（`@取得` と「お題の自動取得」ボタン） | 難易度 1〜4 | 先頭 7,646 語 |

範囲は重なっている。難易度は「その難易度の人が知っていそうな語の上限」を定めるもので、難易度を上げても易しい語をすべて除外するわけではない。「上級者」は難易度 1〜2 の語を、「変態」は難易度 1〜4 の語を除き、それ以外の範囲は下限を持たない。ランダム村のお題は「初心者」の範囲から引く。

### お題辞書

お題は `village/word.csv`（8,436 語）に同梱し、入口が起動時に一度だけ読み込む。

- UTF-8 で読み、不正なバイトは U+FFFD に置き換える。
- 各行の 1 列目がお題、2 列目が難易度（1〜5）。3 列目以降は読まない。難易度は、前後の U+0020 以下の文字を除いてから、数値と同じ規則で読む。
- 難易度の範囲は 2 列目の値から導く。**辞書は難易度の昇順に並べる必要がある。** 行を追加・削除しても境界値を手で直す必要はない。
- 次のどれかに当てはまる辞書は、補完せずに**全体を破棄する**。ファイルが読めない、2 列目が整数として読めない行がある、難易度が 1〜5 の範囲外の行がある、昇順を破る行がある、語のない難易度がある。中途半端な辞書から引くと、違う難易度のお題を黙って配ることになるため。

**辞書を破棄した場合、お題の抽選は「お題なし」を返し、それが `null` としてそのまま応答に現れる。** エラー応答にはならないため、利用者は失敗に気付けない。破棄は起動時の ERROR ログにだけ現れる。

- お題の自動取得は「お題は「null」です。確定しますか？」という候補を返す。「確定」ボタンが送る文字列も `null` である。
- ランダム村は、お題が未設定のまま作成される。インサイダーへは「お題は『null』です。」が配られ、さらにお題が未設定と見なされるため、**オーナーの次の自由文入力がその村のお題として設定される**。

## その他のコマンド

| 入力 | 動作 |
| --- | --- |
| `@配布` / `＠配布` | Bot の友だち追加用の案内（画像・URL・ID）を表示する。画像は役職画像と同じ場所から配信する |
| `@特殊` / `＠特殊` | Web 版の特殊村フォームの URL を表示する。URL は入口が組み立てて渡す |
| スタンプ送信 | 製作者情報と、意見フォーム・ホームページへのリンクを表示する。LINE の入口に固有で、中核は関与しない |

## 対象の村がない場合

操作の対象にできる村が見つからないとき、それは例外ではなく「対象の村がない」という通常の結果になる。

- 存在しない（または消えた）村番号を送った（101〜999 を含む）
- お題・人数・逆村・Werewords の変換に使える自分の村がない（設定済みの村への再設定を含む）
- Werewords の変換の条件（人数 3 人以上、お題の設定済み）を満たさない

このとき、入口は村の作成を促す既定の応答を返す。「村の作成をしますか？」の確認に、「GM」（`お題` を送る）と「神」（`神` を送る）の 2 つの選択肢が付く。`ランダム` は隠しコマンドのため含まれない。LINE は確認テンプレートで出し、Web は次の案内文で出す。

> お題を配りたい方は「お題」または「神」を、
> お題及び役職を確認したい場合は村番号（数字4桁）を入力してください。

## ユーザーを識別できない場合

**LINE の入口に固有。** グループトークやルームでは、利用者が LINE 公式アカウントの利用規約に同意していないと、イベントにユーザー ID が含まれない。ユーザー ID はオーナーと参加者の同一性判定に使うため、**この場合は状態を一切変更せず**、1 対 1 のトークから操作するよう促すメッセージ（「ユーザーを識別できないため操作できません。」から始まる文）を返す。

そのため、**LINE ではこの Bot を 1 対 1 のトークで使うことを前提とする**。秘密情報を配るという目的からも、グループトークでの利用は想定していない。Web の入口は参加者ごとのトークンで識別するので、この状況は起こらない。

## 村の消滅

村はプロセスメモリにのみ存在する。次の場合に消える。

- アプリケーションの再起動・再デプロイ（すべての村が消える）
- 通常村（神モード村・逆村・ランダム村を含む）が 50 件、特殊村（Werewords 村を含む）が 30 件を超えたとき（**古い村から順に消える**）

後者は意図した挙動である。上限を設けなければメモリが際限なく増え、上限で作成を拒否すれば新しい村を作れなくなる。ゲームは数十分で終わり、古い村は使われないという前提のもと、**新しい村の作成を常に成功させる**方を選んでいる。

消えた村の番号を送ると、「対象の村がない」応答になる。進行中の村が消えた場合、オーナーは村を作り直す必要がある。

## 返事モデル

中核は LINE のメッセージ形式でも Web の部品でもなく、経路に依らない返事のデータを返す。LINE と Web の入口が、それぞれの形に描く。

| 返事 | 内容 |
| --- | --- |
| `Text` | 本文だけのテキスト |
| `Image` | 画像（公開された HTTPS の URL） |
| `Buttons` | 本文とボタン。画像、タイトル（人数設定の応答の「N村」の見出し）、`alt_text`、`overflow` を持てる |
| `Confirm` | 本文と 2 つのボタン。`alt_text` を持てる |

返事を返す操作の戻り値は、返事の列である。1 回の操作で複数の返事が返ることがある。

ボタンは 3 種類ある。`MessageAction` は押すとその文字列を送信したことになり、`PostbackAction` は押すと値が入口へ届く。`UriAction` は URL を開く（中核が組み立てる返事には現れない）。

### ボタンの動作

| ボタン | 種類 | 押したときの動作 |
| --- | --- | --- |
| お題の自動取得 | ポストバック `0` | 「指定なし」の範囲から候補を引く |
| 初心者 / 上級者 / 変態 | ポストバック `2` / `3` / `4` | その難易度の範囲から候補を引く |
| 確定 | メッセージ（候補の文字列） | お題を設定する |
| 入室状況確認 | ポストバック（村番号） | 自分の席と入室状況を返す |
| 確認 / 再確認 | メッセージ（村番号） | 村番号を送るのと同じ |
| GM / 神（既定の応答） | メッセージ（`お題` / `神`） | 村を作る |

ポストバックの値は数値で、値域によって意味が変わる。数値でない値は既定の応答になる。

| 値 | 意味 |
| --- | --- |
| 0〜9 | お題候補の取得。`2` 初心者、`3` 上級者、`4` 変態、それ以外は指定なし。ユーザーの識別を必要としない |
| 10〜9999 | 通常村の入室状況確認 |
| 10000 以上 | 特殊村の入室状況確認 |

### overflow

LINE のボタンテンプレートは、本文が画像つきで 60 文字、画像なしで 160 文字までである。お題の長さは利用者が決めるので事前に制限できず、超えることがある。超えたときにボタンを諦めてテキストで送る、という判断を表すのが `Buttons.overflow` で、**表示側が本文を文字数に収められないときに、代わりに出す返事の列**を持つ。メッセージが届かないより、見栄えを落とす方を選ぶ。

- **参加者の役職メッセージ**（インサイダー・特殊村）: 収まらなければ、本文のテキストと入室状況のテキストの 2 通に分ける。ボタンで提供していた「入室状況確認」の代わりに、現在の入室状況を続けて伝える。
- **GM の役職メッセージ**: 画像つきで収まらなければ画像を外したボタン、それでも収まらなければ本文のテキストと入室状況の 2 通、の順に落とす。`overflow` の中にさらに `Buttons` を置いて、この段階を表す。
- **オーナーの配布状況**: 収まらなければ本文のテキスト 1 通だけになる。「再確認」ボタンは付かず、入室状況は本文に含まれる。
- 村人の役職メッセージなど、本文が短い固定文のものは `overflow` を持たない。

入口が本文の文字数を数えて、本体と `overflow` のどちらを出すかを決める。文字数は UTF-16 の符号単位で数える（絵文字は 2 文字）。Python の `len()` のように符号位置で数えると、絵文字を含む本文で LINE の判定とずれる。Web には制限がないので、常に本体を描く。

### alt_text

LINE のテンプレートに添える代替文である。`None` なら本文を使う。村の作成、人数設定、お題候補、既定の応答が持つ。

### 対象の村がない（`None`）

「対象の村がない」は、例外ではなく `None` で返す。村が消えている、まだ作っていない、条件を満たさないことは、いずれも利用者の操作として起こりうる通常の結果だからである。入口が `None` を受け取って、既定の応答（上記）へ変換する。村を作る操作は常に成功するので `None` を返さない。

## 並行性

asyncio は 1 スレッドで動くので、排他制御は要らない。代わりに、**村の 1 操作は同期関数で完結し、途中で `await` を挟まない。** 人数確定と配役抽選、お題設定、逆村化、参加（席の確保と配役）、採番と登録は、それぞれ 1 つの同期関数の中で終わり、途中の状態は他の操作から観測されない。Java 実装が `synchronized` で守っていた保証に相当する。

`await` を含むのは、役職画像のカタログの取り直しだけである。通信を待つ間は村の状態に触れず、受け取った一覧は 1 回の代入で入れ替える。

## 参加者の識別子

オーナーも参加者も、不透明な文字列で識別する。LINE は `line:<ユーザー ID>`、Web は `web:<トークン>` である。中核は接頭辞を解釈せず、文字列が同じかどうかだけを見る。

LINE と Web の同一人物は紐づけない。別の識別子は別人として扱うので、同じ人が LINE と Web の両方から同じ村へ入ると、2 つの席を使う。

利用者の識別子とお題は、ログに出さない。Web のトークンは、そのトークンを知る人がその参加者として振る舞える資格なので、URL にも含めない。

## 役職画像

役職メッセージとオーナー向けの案内に、役職の画像を添える。

既定の画像は `web/static/roles/` に同梱し、自前のドメインの `/static/roles/` から配信する。LINE は画像を HTTPS で公開された URL でしか受け取れないので、URL は入口が渡す公開 URL を基に組み立てる。

| 画像 | 使う返事 |
| --- | --- |
| `INSIDER.png` | インサイダーの役職メッセージ |
| `VILLAGERS.png` | 村人の役職メッセージ |
| `GM.png` | GM の役職メッセージ、神モードでない村の人数設定の応答 |
| `GOD.png` | 神モード村の人数設定の応答 |
| `966mpnqz.png` | `@配布` の友だち追加の案内 |

### 外部カタログ

`ILLUSTRATION_CATALOG_URL` を設定したときだけ、外部カタログから役職画像を重み付きで抽選する。入口は、この環境変数の値をカタログの URL として中核へ渡し、起動直後と以降 5 分ごとに、中核の取り直し（`Illustrations.refresh`）を呼ぶ。未設定なら取りに行かず、既定の画像だけを使う。

カタログは `files` 配列を持つ JSON を返す。各要素は `name` と `url` を持つ。取得ではリダイレクトを辿る。

- `name` の規約: `<役職名>_<重み>_<任意の文字列>` の 3 部構成。`_` で区切り、末尾の空の要素は数えない。この形式でない要素と、`url` が文字列でない要素は、その要素だけ読み飛ばす（1 件の書き間違いで全役職が既定の画像に戻らないように）。読み飛ばした件数は WARNING ログに出る。
- `<役職名>`: `INSIDER` / `VILLAGERS` / `GM` / `GOD`
- `<重み>`: 抽選での出現比率を表す整数（数値と同じ規則で読む）。値が大きいほど選ばれやすい。0 以下の要素は選ばれない。

**取得に失敗した場合**（通信の失敗、HTTP エラー、`files` がない応答）は、前回取得できた一覧をそのまま使い続け、WARNING ログに出す。一度も取得できていない場合、該当する役職名の画像が一覧にない場合、または一覧にあっても重みの合計が 0 以下で抽選できない場合は、既定の画像を使う。画像の取得は配布の本質ではないので、失敗しても配布は続行する。

**URL の指定に関する注意**

Google Apps Script のデプロイ URL（`/macros/s/<デプロイ ID>/exec`）を指定する。ブラウザでこの URL を開くと別ドメインへリダイレクトされるが、**リダイレクト先の URL を設定してはいけない**。リダイレクト先に含まれるキーは一時的な発行物で、失効すると以降エラーを返し続ける。

**この外部化の意図**

画像を差し替えるたびに再デプロイするのを避けるためである。役職画像は見た目の要素であり、アプリケーションのリリースサイクルに縛る理由がない。
